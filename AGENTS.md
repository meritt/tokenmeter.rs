# tokenmeter

Rust core behind a C ABI, shipped as a crate, a WebAssembly npm package and a Swift package. Design: [docs/architecture.md](docs/architecture.md).

## Layout

| Path | Contents |
|---|---|
| `crates/tokenmeter-core` | public Rust API; no `unsafe`, no I/O; `data/o200k_base.tiktoken` is OpenAI's table as published |
| `crates/tokenmeter-ffi` | C ABI; `include/tokenmeter.h` is generated by cbindgen |
| `xtask` | header, corpus, build, release set |
| `packages/npm`, `packages/swift` | bindings; the Swift manifest is `Package.swift` at the root |
| `testdata/o200k.tsv` | reference corpus from tiktoken, pinned by `testdata/o200k.sha256`; never edited by hand |

## Toolchain

rustup (pinned by `rust-toolchain.toml`; not Homebrew `rust`), macOS 26 with Xcode 26, Node.js per `.nvmrc`, pnpm 12, `wasm-opt` from binaryen 133 (`WASM_OPT` overrides the path), `uv` for `cargo xtask corpus`.

## Checks

```bash
cargo fmt --all --check
CARGO_BUILD_WARNINGS=deny cargo clippy --workspace --all-targets --locked
CARGO_BUILD_WARNINGS=deny cargo clippy -p tokenmeter-core -p tokenmeter-ffi --locked --target wasm32-unknown-unknown
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --locked
cargo xtask header --check
cargo xtask corpus --check
cargo deny --locked check
cargo test --workspace --locked
cargo package -p tokenmeter-core --locked
cargo +nightly-2026-11-01 miri test -p tokenmeter-ffi --locked
cargo xtask dist
```

CI runs the same set and `cargo semver-checks` against the last release: `.github/workflows/ci.yml`.

## Rules

- `include/tokenmeter.h`, `tokenmeter-ffi` and the wasm32 offsets in `packages/npm/tokenmeter.js` change together; `cargo xtask header` regenerates the header.
- The macOS floor changes together in `Package.swift` and `MACOS` in `xtask`.
- Corpus update: change the tiktoken version in `testdata/o200k.sha256`, then `cargo xtask corpus`. A corpus failure is a defect in this code. `TOKENMETER_CORPUS` overrides its path.
- `build.rs` refuses a table whose SHA-256 differs from the one tiktoken pins.
- No comments in code beyond `SAFETY:` notes, `# Safety` sections and constraints the code cannot express; design goes to `docs/architecture.md`.
- Commit messages: one Russian line, present-tense verb.

## Release

1. Set `version` in `Cargo.toml` (`[workspace.package]`) and `packages/npm/package.json`; merge to `main`.
2. Take the release set CI built for that commit and pin it:

   ```bash
   gh run download <run-id> --repo meritt/tokenmeter.rs --name release-set --dir /tmp/tokenmeter-set
   ```

   ```bash
   cargo xtask pin /tmp/tokenmeter-set
   ```

3. Merge the pin to `main`, tag it and push the tag:

   ```bash
   git tag -a vX.Y.Z -m "vX.Y.Z"
   ```

   ```bash
   git push origin vX.Y.Z
   ```

4. Once the Release workflow is green, publish the released tarball and the tagged crate:

   ```bash
   gh release download vX.Y.Z --repo meritt/tokenmeter.rs --pattern tokenmeter-vX.Y.Z-npm.tgz --dir /tmp/tokenmeter-npm
   ```

   ```bash
   pnpm publish /tmp/tokenmeter-npm/tokenmeter-vX.Y.Z-npm.tgz --access public
   ```

   ```bash
   git checkout vX.Y.Z && cargo publish -p tokenmeter-core --locked
   ```

Repository settings: immutable releases enabled.

Recovery:

| Failed at | Action |
|---|---|
| Identity, Gates, Build | rerun; for a code fix delete the tag (`git push origin :refs/tags/vX.Y.Z`), fix on `main`, tag again |
| Draft, Readback, Publish | `gh release delete vX.Y.Z --repo meritt/tokenmeter.rs --yes`, rerun |
| Immutability | rerun the failed job |
| Published release is wrong | release the next patch version |
